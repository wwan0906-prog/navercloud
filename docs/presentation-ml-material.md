## 2. 18개 라벨 구성과 라벨링 방법

### 2-1. 원본 라벨은 어떻게 붙었나 (AI허브)
- 라벨링 주체: 데이터 구축 사업자(전문 라벨러). 우리가 직접 라벨링한 것이 아님.
- 라벨 기준: **민원을 실제로 처리한 창원시 담당 부서** 기준의 의도 분류. 그래서 "공원 놀이터"가 산림(산림농정과 소관), "옥외광고물"이 건축허가, "동물 등록"이 농업_축산에 들어감 → 상식과 다른 경계가 있음 (뒤의 오분류 분석과 연결).
- 레코드 구조: 문장(`Q_refined`) + `intent{category, subcategory, predication}` + `entities` + `department`

### 2-2. 우리가 한 것: 18개 → 8개 서비스 분야로 재매핑

앱에서 쓰기엔 18개가 너무 세분화되고 건수 불균형이 심해(정보통신 186건) **8개 분야로 묶음**. 원본 18개는 2단계 "세부 유형"으로 그대로 살림.

| 서비스 분야 (8) | 원본 대분류 (18) | 원문 합계 |
|---|---|---|
| 교통·자동차 | 자동차, 교통 | 95,144 |
| 도로·안전시설 | 안전건설 | 23,436 |
| 건축·토지 | 건축허가, 토지 | 15,837 |
| 환경·위생 | 환경미화, 위생, 상하수도 | 18,771 |
| 산림·농업 | 산림, 농업_축산 | 8,914 |
| 복지·보건 | 복지, 보건소 | 10,229 |
| 세무·행정 | 세무, 행정, 공통, 정보통신 | 18,682 |
| 경제·문화 | 경제, 문화_체육_관광 | 8,987 |

→ 모델 구조: **1단계 튜닝 모델이 8개 분야** → **2단계 프롬프트가 그 분야에 속한 원본 유형(2~4개) 중 선택**

### 2-3. 전처리 (학습·평가 데이터 만들기)

| 단계 | 내용 | 이유 |
|---|---|---|
| ① 대표 문장 추출 | 기준 ID당 원문(`-0`) 1건만 사용 (유사 문장 `-1~-4` 제외) | 같은 문장 5번 학습 방지 |
| ② train/test 분리 | 기준 ID 해시로 10% 분리 → 같은 세트의 문장이 양쪽에 섞이지 않음 | **누수 방지** (아래 참고) |
| ③ 균등 샘플링 | 분야별 학습 400건, 평가 50건 (seed 42) | 자동차 37% 쏠림 보정 |
| ④ 개인정보 | 전화번호·주민번호 정규식 마스킹 (주소·차량번호는 원본에서 이미 `#@주소#` 마스킹) | |
| ⑤ 형식 변환 | CLOVA Studio 튜닝 CSV (`System_Prompt, C_ID, T_ID, Text, Completion`) | |

> **시행착오 1 — Validation 누수 발견**: AI허브가 제공한 Validation 데이터(10만 건)를 평가셋으로 쓰려 했으나, 기준 ID를 대조하니 **Training 원문의 유사 문장이 100% 겹침**. 이대로 평가하면 답을 미리 본 것과 같아 정확도가 과대평가됨 → Validation을 버리고 Training에서 세트 단위로 직접 분리.

> **발표 멘트**: "AI허브가 준 검증 데이터는 학습 데이터의 변형 문장이라 그대로 쓰면 점수가 부풀려집니다. 그래서 세트 단위로 직접 나눠 공정한 평가셋 400건을 만들었습니다."

## 3. Zero-shot · Few-shot · Tuning 설정과 비교 방법

### 3-1. 세 가지 설정

| | Zero-shot (base) | Few-shot (fewshot8) | Tuning (tuned) |

| 프롬프트 | 시스템 프롬프트: 역할 + 8개 분야 이름 + "이름만 출력" | 같은 시스템 프롬프트 + **예시 8개**(분야당 1개, train.csv에서) | 같은 시스템 프롬프트 (예시 없음) |
| 학습 데이터 | 없음 | 없음 (예시만) | **3,200건** (8 × 400) |

| 추론 설정 | temperature 0.01, maxTokens 20 | 동일 | 동일 |
| 학습 시간 | — | — | 약 6시간 (대기 포함) |

### 3-2. 비교 방법 — "같은 시험지, 같은 지시문"

- **평가셋 고정**: 세 설정 모두 **동일한 test.jsonl 400건** (분야별 50건)
- **지시문 고정**: 세 설정 모두 **동일한 system_prompt.txt** (few-shot만 뒤에 예시 추가)
- **정답 판정**: 응답에서 분야 이름을 추출(`normalize`)해 정답과 비교. 가운뎃점·공백·따옴표 차이는 무시
- **도구**: `ml/eval_classifier.py` — 모델만 바꿔 실행, 결과를 `results/<tag>_summary.md`에 저장, `--compare`로 표 생성

> **발표 멘트**: "평가 조건을 완전히 동일하게 두고 모델만 바꿨습니다. 그래서 숫자 차이는 모델 차이입니다."

## 4. 사용한 지표

| 지표 | 정의 | 왜 보나 |
|---|---|---|
| **정확도 (Accuracy)** | 400건 중 분야를 맞힌 비율 | 주 지표. 분야별 50건씩 균등이라 macro-average recall과 같음 |

| **혼동 조합** | 정답 → 예측 빈도 | 어떤 경계에서 헷갈리는지 |

## 6. 잘못 분류된 사례와 해석

### 6-1. Zero-shot: "상식"으로 분류해서 틀림

| 정답 → 예측 | 건수 | 예시 |
|---|---|---|
| 교통·자동차 → 도로·안전시설 | **42** | "횡단보도 위 불법주정차 단속 원합니다" |
| 산림·농업 → 도로·안전시설 | 16 | 공원·가로수 민원 |
| 건축·토지 → 도로·안전시설 | 10 | |

- "도로·안전시설"이라는 이름이 넓게 들려 **도로 위에서 생긴 일은 전부 여기로** 보냄 (과잉 분류 82건)
- 불법주정차는 우리 기준(원본 데이터 기준)으로 교통·자동차인데, 모델은 "도로 문제"로 봄
- → **모델이 틀린 게 아니라 우리 분류 기준을 모르는 것**

### 6-2. Few-shot: 보여준 경계만 배움

| 변화 | 수치 |
|---|---|
| 교통·자동차 | 14% → 88% (불법주정차 예시 1개가 경계를 고침) |
| 산림·농업 | 28% → 22% (예시 없는 경계는 그대로/악화) |
| 경제·문화 | 52% → 44% |

- 산림·농업 → 도로·안전시설 **25건** (zero-shot 16건보다 늘어남)
- → 예시 8개로는 8개 분야의 모든 경계를 못 가르침. 오히려 예시 문장에 끌려 다른 분야가 흔들림

### 6-3. Tuning 후 남은 오류 (102건)

| 정답 → 예측 | 건수 | 원인 |
|---|---|---|
| 산림·농업 → 경제·문화 | 7 | 공원·체육시설 경계 |
| 세무·행정 → 경제·문화 | 7 | 행정·공통(진정·건의)이 섞여 경계가 흐림 |
| 도로·안전시설 ↔ 건축·토지 | 6 + 6 | 시설물 vs 건축물 |
| 세무·행정 → 환경·위생 | 5 | |

틀린 예시 (tuned):
- 「진해보건소 지하 1층 시설팀 전화번호 문의」 정답 도로·안전시설 → 예측 복지·보건
- 「창원시 논 둑 유실 복구 공사 문의」 정답 도로·안전시설 → 예측 산림·농업
- 「안민고개 사거리 조경이 이쁘지 않습니다」 정답 도로·안전시설 → 예측 산림·농업

→ 이 예시들은 **정답 라벨 자체가 "처리 부서" 기준이라 상식과 어긋남**. 모델 예측이 오히려 자연스러운 경우가 많음. 라벨 노이즈로 인한 상한이 있어 **75~85%가 현실적 상한**.

### 6-4. 도로·안전시설만 떨어진 이유 (78% → 68%)
zero-shot은 뭐든 도로·안전시설로 보내서 **recall이 높았던 것**(과잉 분류 82건의 부산물). 튜닝 후 과잉 분류가 사라지며 정직한 점수로 내려옴. 전체 정확도는 올랐으므로 이득.

> **발표 멘트**: "Zero-shot은 불법주정차 42건을 전부 도로·안전시설로 보냈습니다. 예시 8개를 주면 그 경계는 고쳐지지만 다른 경계가 흔들립니다. 같은 데이터 3,200건으로 튜닝하자 예시로 못 가르친 경계까지 배워 74.5%가 됐고, 출력 형식도 고정됐습니다. 남은 오류는 라벨이 실제 처리 부서 기준이라 상식과 다른 경우가 대부분입니다."

## 7. 개선 과정 (History 요약)

| 순서 | 한 일 | 결과/발견 |
|---|---|---|
| 1 | AI허브 데이터 분석 | Validation이 Training의 유사 문장(100% 겹침) → 자체 분할 |
| 2 | 18→8 재매핑, 균등 샘플링, CSV 변환 | train 3,200 / test 400 |
| 3 | Zero-shot 측정 | 49.8%. 불법주정차 42건 전부 도로·안전시설 |
| 4 | Few-shot 8 측정 | 56.8%. 보여준 경계만 개선, 형식은 예시에 끌려감 |
| 5 | LoRA 튜닝 (3,200건, 8 epoch, lr 1e-4) | **74.5%**. 형식 100% 고정 |
| 6 | 오류 분석 | 라벨 노이즈 확인 → 상한 인식, v2는 분야별 800건 검토(시간 되면) |
| 7 | 파이프라인 샘플 60건 테스트 | 분류 약 95% (깨끗한 문장 기준). 오류 3건: 공사장 낙석→건축, 관광지 화장실→공통, 정류장 이전→안전건설 |

**한계로 말할 것**
- 라벨 노이즈로 인한 상한 (처리 부서 기준 라벨)
- 세무·행정 58%: 행정·공통·정보통신을 한 분야로 묶어 경계가 흐림
- 창원시 데이터 기반 → 다른 지역 적용 시 부서 기준이 다를 수 있음

**향후**
- 분야별 800건으로 v2 튜닝
- 틀린 샘플(공사장 낙석 등) 유형을 학습 데이터에 보강
- 사용자 피드백("분류가 맞았나요?")을 재학습 데이터로

## 8. 슬라이드 구성 제안 (이 자료 기준, 4~5장)

1. **데이터** — 출처·20만 건·18개 라벨 분포 표 (1절)
2. **전처리** — 18→8 매핑 표 + 누수 발견 한 줄 (2절)
3. **실험 설정** — Zero/Few/Tune 비교표 + "같은 시험지" (3절)
4. **결과** — 종합 3단 막대 + 분야별 그룹 막대 (5절)
5. **오류 분석과 한계** — 혼동 조합 상위 3개 + 틀린 예시 2개 + 상한 설명 (6·7절)
